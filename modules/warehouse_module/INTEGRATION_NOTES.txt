Part catalog routes:

Part catalog note:
- parts_catalog now has is_consumable BOOLEAN NOT NULL DEFAULT FALSE.
- is_consumable=false means the same part cannot be active twice on the same vehicle.
- is_consumable=true means repeated active usage on the same vehicle is allowed.

Part request status seed data:
- 1 = new      / Новая
- 2 = rejected / Отклонена
- 3 = approved / Утверждена

- GET    /api/warehouse/part-requests/:id         (admin, duty_mechanic, warehouse_manager)
- PUT    /api/warehouse/part-requests/:id         (admin, duty_mechanic, warehouse_manager; blocked if current status is approved/rejected)

Vehicle part installation routes:

- GET    /api/warehouse/vehicle-part-installations               (admin, duty_mechanic, warehouse_manager)
- GET    /api/warehouse/vehicle-part-installations/:id           (admin, duty_mechanic, warehouse_manager)
- PUT    /api/warehouse/vehicle-part-installations/:id           (duty_mechanic, warehouse_manager)
- PATCH  /api/warehouse/vehicle-part-installations/:id/activity  (duty_mechanic, warehouse_manager)
- DELETE /api/warehouse/vehicle-part-installations/:id           (duty_mechanic, warehouse_manager)

Vehicle part installation business rules implemented:
- part_id must exist in parts_catalog.
- vehicle_id must exist in vehicles.
- quantity must be greater than 0.
- On create, parts_catalog.quantity is decreased inside one DB transaction.
- If stock quantity is not enough, installation is rejected.
- Non-consumable part cannot be simultaneously active twice on the same vehicle.
- Consumable part can be installed repeatedly.
- Repeated installation is inserted as a new exploitation/history record.
- installed_by_user_id is taken from JWT context user_id on create.
- PUT can correct part/vehicle/date/quantity/installer/is_active and safely adjusts warehouse stock.
- DELETE removes the record and returns its quantity back to warehouse stock.
- PATCH /activity only changes is_active; use it to close old exploitation record before installing the same non-consumable part again.

Vehicle passport integration:
- GET /api/vehicles/:id and GET /api/vehicles now include installed_parts in the vehicle response.
